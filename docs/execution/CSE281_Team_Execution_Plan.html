1. Project overview and course requirements

1.1 Goal

Deliver a working classical image-processing pipeline for a real problem on real, imperfect images, together with evidence that it works and an honest account of where it fails. The final output must be a measurement or a decision (a count, area, location, pass/fail or clean binary image), and reaching it must require separating objects from the background. The marking rewards rigour over attractive images.

Hard constraints from the specification. (1) No neural networks and no machine-learning models. Projects whose result depends on a learned model are not accepted. (2) A one-call solution that hides the whole task (a ready-made detector or segmenter) is not accepted. (3) Python 3 with NumPy, OpenCV, scikit-image, SciPy and Matplotlib. (4) The test set must run in under 10 minutes on a free Colab CPU. (5) No private or scraped personal data.

Problem formulation (approved 19 Nov 2026)

A building-inspection engineer surveys concrete walls and slabs and needs to know where the cracks are and how much of the surface is cracked. The pipeline takes one photo and outputs a binary crack mask, the cracked-area percentage, the crack length (pixels along the mask skeleton) and a severity class (minor / moderate / severe). A missed crack means structural damage may go unrepaired, which is a safety cost. A false crack (a stain, shadow edge or pore) wastes inspection time and lowers trust in the tool. Cracks are only about 1.4% of the pixels, so pixel accuracy is misleading: an empty mask would score about 98.6%. The primary metric is IoU of the crack class, because it ignores the easy background and penalises both missed and false crack pixels. Dice/F1 and the absolute error of crack-area % are secondary.

InputOutputPrimary metricSecondary
RGB JPEG, 8-bit, 4032×3024 or 3264×2448, converted once to gray uint8 and resized so the long side equals the working size L (chosen by the resolution study) bool crack mask (H×W at size L); crack area %; skeleton length; severity class IoU (crack class), per image, mean ± std Dice/F1; |area % error|; severity accuracy vs the class computed from the GT mask

Conventions everyone must follow (fixed now, so modules plug together):

  • Between stages: grayscale images are np.uint8 in [0, 255] with shape (H, W). Masks are np.bool_ with shape (H, W). Inside a function you may work in float64, but you must convert back to the stage output type.
  • Default border handling for neighbourhood operations: reflect-101, which is np.pad(mode="reflect") = cv2.BORDER_REFLECT_101 = scipy.ndimage mode="mirror". Note that NumPy "symmetric" equals OpenCV BORDER_REFLECT equals SciPy "reflect". The names do not line up, so always state which one you use.
  • Kernels are applied as correlation (OpenCV filter2D convention). For symmetric kernels this is the same as convolution.
  • Colour: OpenCV loads BGR. data.load_image converts once, and only there. Convert BGR to RGB before any matplotlib display.
  • Every function that uses randomness takes a seed argument and uses np.random.default_rng(seed). Nothing uses global RNG state.
  • Every stage function is pure: image in, image out, parameters as keyword arguments. No file I/O inside stage functions.
  • Docstrings on every public function. Lines of at most 95 characters. No hard-coded paths (paths come from config or CLI).
  • Working size: load_image resizes once (INTER_AREA) so the long side is L. Masks are resized the same way (INTER_AREA, then ≥ 0.5). All metrics are computed at size L.

19.1 MEM1 — data, metrics, baselines, architecture

Hand-worked example (must match the code output)

a = [[10,20],[30,40]]   b = [[12,20],[30,36]]
diff = [[-2,0],[0,4]] -> squares 4,0,0,16 -> MSE = 20/4 = 5.0

pred = [[1,1,0],[1,0,0],[0,0,0]]  gt = [[1,0,0],[1,1,0],[0,0,0]]
|pred AND gt| = 2,  |pred OR gt| = 4  ->  IoU = 0.5
Q: Why compute MSE in float and not on uint8 arrays?
uint8 subtraction wraps modulo 256: 10 − 12 gives 254, not −2. That would make the MSE wrong. We cast to float64 first.
Q: Why is 255² in the PSNR formula, and what happens when MSE = 0?
255 is the maximum possible pixel value for 8-bit images, so PSNR measures the error relative to the peak signal power. When MSE = 0 the images are identical and PSNR is infinite. We return inf and handle it in averages.
Q: Why IoU rather than pixel accuracy?
When the foreground is small, predicting all background scores high accuracy while finding nothing. IoU ignores true negatives and penalises both missed and spurious foreground. Here cracks are about 1.4% of the pixels, so an empty mask scores about 98.6% accuracy but IoU 0. A missed crack (unrepaired damage) and a false crack (wasted inspection) both lower IoU.
Q: How did you make sure the test set was not used for tuning?
The split is fixed with a seed and committed. All studies read only the dev list. The final config was tagged results-frozen before evaluate --split test ran, and that run happened once (visible in git and in the log).
Q: Why both a trivial and a simple baseline?
The trivial baseline shows how hard the task is with no processing at all. The simple baseline is a reasonable minimum effort. A complex pipeline is only worth its complexity if it beats the simple baseline, and where it doesn't, we explain why.
Q: Why report mean ± std over three seeds?
Noise is random, so a single run could be lucky. The std shows how sensitive the pipeline is to the particular noise sample.

19.2 MEM2 — enhancement

Histogram equalization, 3-bit (L=8), 3x3 image [[0,0,1],[1,1,2],[2,3,7]]
counts: r0=2 r1=3 r2=2 r3=1 r7=1   CDF: 2/9, 5/9, 7/9, 8/9, ..., 9/9
s = round(7*CDF): 0->2, 1->4, 2->5, 3->6, 7->7

Mean 3x3 on [[1,2,3],[4,5,6],[7,8,9]] centre -> 45/9 = 5
Log: s = (255/ln 256) ln(1+r); r=15 -> 255*ln16/ln256 = 127.5
Output size: (N - F + 2P)/S + 1 = (5 - 3 + 2)/1 + 1 = 5
Q: Why does histogram equalization sometimes make segmentation worse?
It spreads intensities using the global CDF, so it also amplifies background texture and noise, and it can merge the foreground and background distributions. Gains in visible contrast don't guarantee separability.
Q: Gaussian or mean filter, and why?
Gaussian weights fall off smoothly, so it blurs edges less and has no ringing in the frequency domain (its transform is also Gaussian). The mean filter's box has a sinc-shaped response with side lobes.
Q: How does Laplacian sharpening work, and what is its risk?
g = f − ∇²f (with the centre-negative kernel) adds back second-derivative detail at edges. It also amplifies noise, so it should come after smoothing.
Q: How does your gradient sharpening work, and why not just add the gradient?
We use the Gonzalez & Woods “combining spatial enhancement methods” scheme. The Sobel magnitude is smoothed with a 5×5 mean, normalized to [0,1] and used as a mask: g = f + Ms·(flap − f). The Laplacian detail is added only where edges are strong, so noise in flat regions, where the gradient is small, is not amplified. Adding |∇f| directly would only brighten edges without restoring their profile.

19.3 MEM3 — restoration and frequency

3x3 window [[10,12,11],[13,255,12],[11,10,0]]  sorted: 0,10,10,11,11,12,12,13,255
median=11  mean=334/9=37.1  max=255  min=0  midpoint=(0+255)/2=127.5
alpha-trimmed d=2: drop 0 and 255 -> 79/7 = 11.29
Butterworth LP at D=D0: 1/(1+1^(2n)) = 0.5 ;  Gaussian LP at D=D0: e^-0.5 = 0.607
Q: Why is the median better than the mean for salt-and-pepper noise?
Impulses are extreme outliers. The mean includes them (37.1 above), but the median ignores them as long as fewer than half the window is corrupted (11 above).
Q: Why does the ideal low-pass filter ring?
Its sharp cutoff in frequency corresponds to a sinc in space. Convolving with a sinc produces oscillations near edges. Butterworth (low order) and Gaussian roll off smoothly and reduce or remove the ringing.
Q: Why multiply by (−1)x+y, and why pad?
The multiplication shifts F(u,v) by (M/2, N/2), which puts DC at the centre for display and for filter design. The DFT assumes periodicity, so padding to 2M×2N prevents wrap-around artefacts from circular convolution.

19.4 MEM4 — segmentation

Patch [[10,10,10],[10,10,10],[200,200,200]], correlation with Sobel:
Gx = [[-1,0,1],[-2,0,2],[-1,0,1]] -> 0
Gy = [[-1,-2,-1],[0,0,0],[1,2,1]] -> -(10+20+10) + (200+400+200) = 760
|grad| = sqrt(0^2 + 760^2) = 760   (horizontal edge)
Q: What does Otsu maximise, and when does it fail?
The between-class variance σ²B, which is the same as minimising the within-class variance. It assumes a bimodal histogram. It fails when the object is a tiny fraction of the pixels or when uneven illumination shifts the modes. That is why adaptive thresholding exists.
Q: Why apply LoG rather than the plain Laplacian?
The Laplacian is a second derivative and very sensitive to noise. Gaussian smoothing first, with σ setting the scale, suppresses noise. Edges are located at zero crossings.
Q: Sobel vs Prewitt?
Sobel weights the centre row or column by 2, which gives slight smoothing and better noise tolerance. Prewitt weights them equally.

Q: Opening vs closing: which removes what?
Opening (erode then dilate) removes foreground specks smaller than the SE and breaks thin bridges. Closing (dilate then erode) fills small holes and gaps and joins broken parts. The order matters, which is why it is one of our ablations.
Q: How did you choose the SE shape and size?
